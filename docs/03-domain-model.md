# 03 — Domain model

Plain data, no classes. All types live in `@rungs/core`. Field names are indicative; final names are
settled during Phase 1 and then recorded here.

## Overview

```
FlowDefinition (key, version) ──1:N── StepDefinition
        │ pinned by
        ▼
Request ──1:N── StepInstance ──1:N── Task
   │
   └──1:N── AuditEvent (append-only)

DelegationRule (independent, per user)
```

## FlowDefinition

Immutable once registered. A change creates a new `version`.

| Field | Type | Notes |
| --- | --- | --- |
| `key` | string | Stable identifier, e.g. `"expense"` |
| `version` | number | Incremented on every change |
| `steps` | StepDefinition[] | Ordered |
| `onEmptyStep` | `"skip" \| "fail"` | Default when a step resolves to no approvers (Pro adds `"escalate-up"`) |
| `dedupeApprovers` | `"none" \| "consecutive" \| "all"` | Collapse repeated approvers |
| `allowSelfApproval` | boolean | Default `false` |
| `returnPolicy` | `"restart" \| "from-returned-step"` | What runs again after resubmit |

## StepDefinition

| Field | Type | Notes |
| --- | --- | --- |
| `id` | string | Unique within the flow |
| `name` | string? | Display name |
| `approvers` | ApproverSpec | Who decides |
| `mode` | `"any" \| "all" \| { quorum: number }` | Default `"any"` |
| `rejectPolicy` | `"any-reject-rejects" \| "majority"` | For `all` and quorum |
| `when` | Condition? | Step runs only if true; evaluated on the payload snapshot |
| `deadline` | ISO 8601 duration? | e.g. `"P2D"`, `"PT8H"` |
| `remindBefore` | ISO 8601 duration? | Emit a reminder event before the deadline |
| `onTimeout` | `"remind" \| "escalate" \| "auto-approve" \| "auto-reject"` | Default `"remind"` |
| `escalateTo` | ApproverSpec? | Target for `"escalate"` (Pro allows org-relative targets) |

## ApproverSpec

```ts
type ApproverSpec =
  | { type: "users"; ids: string[] }
  | { type: "role"; role: string }                       // host resolves role -> users
  | { type: "resolver"; name: string; params?: unknown } // named resolver (host or Pro)
  | { type: "union"; of: ApproverSpec[] };
```

## Condition (JSON rule language, no code execution)

```ts
type Condition =
  | { field: string; op: "eq" | "neq" | "gt" | "gte" | "lt" | "lte" | "in" | "nin"; value: unknown }
  | { all: Condition[] }
  | { any: Condition[] }
  | { not: Condition };
```

`field` is a dot path into the request payload snapshot.

## Request

| Field | Type | Notes |
| --- | --- | --- |

## StepInstance

Created when a step **activates** (not at submit). Approvers are resolved at activation and the result
is stored as a snapshot.

| Field | Type | Notes |
| --- | --- | --- |
| `stepId` | string | From the definition |
| `status` | `"skipped" \| "active" \| "approved" \| "rejected" \| "returned" \| "cancelled"` | |
| `resolvedApprovers` | string[] | Snapshot after self-approval removal, dedupe and delegation |
| `resolution` | object | Why each approver is there (resolver name, delegation, escalation) — shown in UI and audit |
| `activatedAt`, `deadlineAt`, `closedAt` | ISO string | |
| `escalationDepth` | number | Guards against infinite escalation |

## Task

| Field | Type | Notes |

| `status` | `"pending" \| "approved" \| "rejected" \| "returned" \| "superseded" \| "cancelled" \| "expired"` | |
| `decidedAt`, `comment` | | |

## AuditEvent (append-only)

| Field | Type | Notes |
| --- | --- | --- |
| `requestId` | string | |
| `seq` | number | Monotonic per request |
| `type` | string | e.g. `request.submitted`, `task.approved`, `step.skipped`, `task.delegated` |
| `actorId` | string? | `null` for system actions (tick) |
| `at` | ISO string | |
| `data` | JSON | Event-specific details, including reasons |

Audit events are the source of truth for "what happened and why". Domain events emitted to the host for
notifications are derived from them.
